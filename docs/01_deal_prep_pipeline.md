# 01. 商談前リサーチ・提案生成パイプライン

## 課題
- 商談前の準備（企業調査・仮説・資料）に営業1人あたり毎回30分。提案資料は1時間。品質は担当者の経験に依存
- 「準備した人が受注する」のは分かっていても、件数が増えると準備が削られる

## 何を作るか決めた理由
- 準備の中身を分解すると、企業HP・IR・求人情報の収集と、過去事例との照合が大半。判断が要るのは仮説の最後の一歩だけ
- なら「商談が入った瞬間に、判断の材料が揃っている」状態を自動で作り、営業は仮説の磨き込みと商談に集中させる

## 設計
```
カレンダーの商談を検知 → 企業HP・IR・求人情報を収集 → 競合・NG業種を判定
→ 仮説レポート／トークスクリプト／提案スライド／ナレーション動画／顧客専用ページを生成 → 担当営業へ Slack 通知
```
- 導入事例57社のコーパスと競合判定ルールは**コードから分離**して保守（営業が自分で直せる）
- 処理済み台帳で二重生成を防止。他事業へ引き継げるよう手順書化

## 実装
- Python／Gemini API／Google Apps Script（PPTX → Google スライド変換）／Slack API
- スライドは設定ファイル → 生成スクリプトで組み立て。数字は台帳から引き、文面だけ AI が書く
- ナレーション動画は ElevenLabs で音声生成し、スライドと合成

## 検証
| 指標 | 前 | 後 |
|---|---|---|
| 商談準備 | 30分 | 3分 |
| 提案資料 | 1時間 | 5分 |

- **最初に外した仮説**: 「レポートを全部自動で書けば読まれる」。実際は長いレポートは読まれず、仮説3行＋根拠リンクの形に変えてから使われ始めた

## 運用改善
- 競合・NG 判定の誤りは営業から Slack で返してもらい、ルールファイルに追記（AI の判断ではなく表の修正で直す）
- 事例コーパスは新しい導入事例が公開されるたびに追加。商談で「似た事例」が出る確率を上げる

## 守り・責任分界
- 収集するのは公開情報のみ。社外へ出る資料は営業が商談で使うかどうかを判断する（自動送付はしない）
