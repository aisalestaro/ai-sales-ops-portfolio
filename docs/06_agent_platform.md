# 06. 無人で回す AI エージェント基盤（新規事業のプロトタイプ）

## 課題
- 営業・マーケの定型業務（SNS 投稿・記事公開・フォーム営業の下書き・週次の振り返り）を、人がいなくても回せるか。AI 新規事業のプロトタイプとして検証

## 何を作るか決めた理由
- 「AI に毎回頼む」のではなく、**手順書（SKILL.md）を定時に機械が実行し、失敗を機械が検知し、改善を機械が起票する**ところまで作って初めて「無人」と言える

## 設計
```
launchd（cron 相当） → ラッパー → claude -p "<SKILL.md>" --chrome
   ├ 実行ロック（二重起動防止）
   ├ ネット断：疎通プローブで復旧を待つ。本体着手後の断は再実行しない（二重投稿防止）
   ├ 最終行 STATUS: OK|WARN|FAIL|ASK|LIMIT|OFFLINE を読む
   └ notify → FAIL/CRASH/TIMEOUT は改善キューへ fix_broken 起票＋メール／ASK はダッシュボードの「決める」カード
watchdog（10:05／18:05／23:58）→ 今日発火すべき枠と実行ログを突合。未発火・登録不足を起票。中断した枠は1回だけ再実行
日次（4:43）→ fix_broken だけを自動修復（最大3件・スナップショット必須）
週次（木 1:07）→ PDCA：効いているかを判定し、次の改善を起票
```

## 実装
- 定時ルーティン **38本**（2026-10-04 時点・登録簿の有効分）。Python 61本・約2.2万行、Claude Code スキル 44本
- cron 式 → launchd plist 変換。再登録時に実行中ジョブを殺さない → [`samples/cron_to_launchd.py`](../samples/cron_to_launchd.py)
- 認証はルーティン専用の設定ディレクトリに分離（人のログイン状態と無関係に動く）。Claude API は使わず CLI の定額枠
- 台帳は `ledger_io` で保護。社外文面は `copy_guard` で機械監査

## 検証
- SNS 投稿・記事公開・フォーム営業の下書き・週次 PDCA・改善案の自動適用までを無人化
- 稼働率は朝の日次メールに「昨日 N/M 枠 OK」で出る。未発火・二重発火はゼロが続く状態を維持
- **最初に外した仮説**: 「デスクトップアプリの定時タスクで十分」。アプリがそのアカウントでログイン中しか動かず、別アカウントで作業する数時間ルーティンが止まった → launchd＋CLI に移行

## 運用改善
- 失敗が2回続いた項目は自動で人の判断へ格上げ。人にしかできない作業（認証・課金・権限）だけを「作業待ち」として表示し、それ以外の理由で人へ戻すことを禁止

## 守り・責任分界
- 投稿・送信など対外に出るものは、既定を「下書きまで」とし、送信は本人の明示切替のみ
- 「自動実行／人が判断」は種別で機械判定 → [docs/07](07_kaizen_loop.md)
