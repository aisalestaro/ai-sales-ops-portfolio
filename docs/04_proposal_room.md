# 04. 顧客専用ページ（提案ルーム）と上申支援

## 課題
- 前職で、部長の合意まで取れていた案件を経営層への提案で失注。**担当者は納得しても、上司を説得できない**失注が多い
- PDF を配ると社内でどう回ったか分からず、次の一手が打てない

## 何を作るか決めた理由
- 決裁者が「見るだけで済む」ものを担当者に渡す。かつ、誰がいつ見たかを把握して合意形成の進み具合を測る

## 設計
```
商談後 → その会社専用の提案ページを生成（キーメッセージ → 上申動画 → 現状 → 原因 → 解決策 → 実測 → 比較 → 料金 → 予約）
→ 推測不能トークン URL で共有（noindex・閲覧ゲート）
→ 閲覧イベント（滞在・クリック・新規閲覧者）を記録 → 決裁者閲覧を検知したら次の一手を提案
```
- ページ構成（型）は人が決めたテンプレート。AI は文脈を埋めるだけ

## 実装
- Next.js の動的ページ（`/room/[token]`）。PostgreSQL（Neon）に閲覧イベントを保存
- 上申用ナレーション動画は自動生成（スライド＋音声合成）
- 閲覧イベントは案件管理 OS が毎時吸い上げ、フェーズ判定の材料にする

## 検証
- 顧客専用ページ＋上申動画・資料で、受注率 **8%→45%**（他施策との合算）
- 「決裁者が見た」が分かるので、提案後の放置が減った

## 運用改善
- 離脱が多いセクションを閲覧ログで見て、テンプレの順序を入れ替え（例：実測数字を前に）

## 守り・責任分界
- URL は推測不能トークン・noindex・閲覧ゲート。PDF を配らないので拡散を制御できる。公開・送付は人が行う
