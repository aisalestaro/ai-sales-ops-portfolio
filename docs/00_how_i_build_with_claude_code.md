# 00. Claude Code でどう作っているか

非エンジニアの営業責任者が、要件定義から本番運用までを一人で回すために作ってきた「開発環境の使い方」です。
ポイントは、AI に口頭で頼むのではなく **ルール・手順・ガードをファイルに落として、AI にも人にも同じものを守らせる** ことです。

## 1. 層の分け方

| 層 | 置き場所 | 役割 | 例 |
|---|---|---|---|
| ルール | `CLAUDE.md`（グローバル／プロジェクト） | 毎回守らせること。事故が起きるたびに1項目ずつ追記 | 台帳は ledger_io 経由／施策は改善キューへ起票／触ったファイルだけコミット |
| 手順 | `~/.claude/skills/<name>/SKILL.md`（44本） | 繰り返す業務の手順書。人が読んで同じ作業ができる粒度 | 商談準備／記事生成→下書き保存／面談対策メモ／資料生成 |
| 定時タスク | `~/.claude/scheduled-tasks/<name>/SKILL.md` ＋ launchd | 無人で回す手順。「他にやることを探さない」「対象なしなら即終了」を明記 | 朝の SNS 投稿／週次 PDCA／日次の故障修復 |
| ガード | `settings.json` の hooks | AI の裁量で破られうるルールを機械で止める | PreToolUse で危険なツールを拒否／Stop で自動コミット |
| 記憶 | memory ディレクトリ | 本人の判断・好み・禁止事項を1ファイル1事実で保存 | 「社外文面で比喩 KPI を使わない」「応募文面に居住地を書かない」 |

サンプル: [`samples/claude-code/CLAUDE.md.example`](../samples/claude-code/CLAUDE.md.example) ／ [`SKILL.md.example`](../samples/claude-code/SKILL.md.example) ／ [`settings.hooks.example.json`](../samples/claude-code/settings.hooks.example.json)

## 2. 無人実行のしくみ

```
launchd（cron 相当） → run_task.py（ラッパー） → claude -p "<SKILL.md の手順>" --chrome
                              ├ 実行ロック（同じタスクの二重起動を防ぐ）
                              ├ ネット断なら疎通プローブで復旧を待ち、本体着手後は再実行しない（二重投稿防止）
                              ├ 最終行の STATUS: OK|WARN|FAIL|ASK を読む
                              └ notify.py → FAIL は改善キューに起票＋メール／ASK はダッシュボードの「決める」カード
watchdog（1日3回） → 今日発火すべき枠と実行ログを突合し、未発火を起票
```

- cron 式 → launchd plist の変換と「実行中のジョブを殺さない再登録」: [`samples/cron_to_launchd.py`](../samples/cron_to_launchd.py)
- 認証はルーティン専用の `CLAUDE_CONFIG_DIR` に分離。人がどのアカウントで作業していても止まらない
- Claude API は使わず CLI の定額枠で回す（`ANTHROPIC_API_KEY` を環境から外す）

## 3. 事故から作ったルール（抜粋）

| 起きたこと | 作ったもの |
|---|---|
| 2本のルーティンが同じ JSON を書き、後勝ちで更新が消えた（警告なし） | `ledger_io.py`：ロック＋原子的書き込み＋3-way マージ |
| 新しいタスクを1本登録したら、その瞬間走っていた別タスクが SIGTERM で死んだ | `--install` は plist 未変更なら触らない・実行中はスキップ |
| AI が「迷ったら提案」で8件全部を人に上げ、改善が1週間止まった | 種別で auto/ask を機械判定する `kaizen_policy`。直す・減らすは自動、増やす・払う・送る・消すは確認 |
| 「どのブラウザを使いますか」と毎回聞かれ、全 Chrome に接続要求が出て作業が止まった | PreToolUse フック `browser_guard.py` で該当ツールと質問を拒否 |
| 右下の「コミット」ボタンの押し忘れが続いた | Stop フック `git_autocommit.py`：そのセッションが触ったファイルだけ即コミット、他セッションの編集途中は巻き込まない |
| 移動中にネットが切れ、5記事生成が最初からやり直しになった | `_checkpoint.md`：1ユニットずつ「生成→保存→記録」で閉じ、再開時は完了済みをスキップ |
| 改名した用語が、予約投稿の在庫に残って再発した | 「用語を改名したら下書き・予約の在庫まで洗う」をルール化し、`copy_guard.py` で機械監査 |

## 4. 一人で回すときの分担の考え方

- **自分でやる**: 要件定義、業務フロー設計、プロトタイプ、本番の初期実装、運用・監視、改善ループ
- **エンジニアと分担する前提**: 大規模化、権限設計のレビュー、SLA が要る本番基盤、セキュリティ監査
- 情シスからの問いには「データの行き先・権限・出口統制・記録・障害時・責任分界」の6点の順で答えられる状態を保つ
