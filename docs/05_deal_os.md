# 05. 案件管理 OS（入力ゼロで動く自作 SFA）

## 課題
- 既製の SFA は「人が入力する前提」。入力されないので、案件の状態・次の一手・放置検知が機能しない

## 何を作るか決めた理由
- 入力画面を作らない。**接点（フォーム・メール・Meet・提案ページ閲覧）から自動で台帳が埋まる**ようにし、AI が次の一手を下書きし、人は承認だけする

## 設計（人が触るのは4カ所）
```
接点                     取り込み（毎時・冪等）          台帳（正本）              AI                         出力（社外へ出る手前）
HP フォーム ─┐                                                                                       ┌→ Gmail 下書き ──→ 👤 承認して送信
Gmail スレッド ─┼→ fetch → meet → events → link → think → sync →  deals / contacts / activities  → Claude（新規活動のある案件だけ） ─┼→ 提案ルーム
Meet 文字起こし ─┤      messageId / fileId / eventId を記録        判定表 stage_master（8フェーズ×ルーブリック×SLA） フェーズ判定・次の一手・下書き   ├→ 経営ダッシュボード → 👤 決裁
提案ルーム閲覧 ─┘      決められないものは unlinked_queue へ（無音で捨てない）                                                    └→ 改善キュー
```
人が触る4カ所＝①承認して送信 ②商談に出る ③受注・失注の確定 ④施策の決裁

## 実装
- 取り込み：GAS（担当者本人の権限・既存スコープのみ・新規 OAuth なし）＋ Python バッチ（launchd 毎時）
- 台帳：JSON（ロック＋原子的書き込み＋3-way マージ）。非公開 git に入れるので変更履歴がそのまま監査証跡 → [`samples/ledger_io.py`](../samples/ledger_io.py)
- AI 層：Claude ヘッドレス。**人が書いた判定表に従って**フェーズ判定（根拠つき）・次の一手・会社ドシエ・メール下書き。表に無い判断はしない
- ネクストアクションの正規化：推奨は1〜3件に絞る。却下済みは再掲しない。同じ宛先に未送信下書きが2件以上なら統合。同一宛先への20時間以内の連投を機械的に拒否
- 無音失敗ガード：実行結果を必ず状態ファイルに書き、日次ダッシュボードが監視

## 検証
- フォーム送信から、一次返信の下書き・会社リサーチ・フェーズ判定・提案ページ生成まで **7分**。人がキーボードに触れるのは最後の承認1回
- **最初に外した仮説**: 「AI に次の一手を自由に出させる」。推奨が5〜8件並んで誰も読まなくなり、1〜3件に絞る正規化を入れてから承認率が上がった

## 運用改善
- 却下された次の一手は台帳に残し、同じ提案を二度と出さない
- 判定表（フェーズ定義・SLA）は営業マネージャーが直す。AI のプロンプトは触らない

## 守り・責任分界（情シスの6問の順）
1. データの行き先：Workspace 内と自社 DB。LLM に渡すのは活動の事実と判定表のみ
2. 権限：担当者本人の権限で動く GAS。新規 OAuth 同意を増やさない
3. 出口統制：送る・公開する・払う・消すは人。連投ガード
4. 記録：全活動ログ（activities）と git 履歴
5. 障害時：冪等なので再実行で復旧。無音失敗は日次で検知
6. 責任分界：送信・公開・受注失注・決裁は AI が決めない
