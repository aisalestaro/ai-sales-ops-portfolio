# 07. 自己改善ループ（改善キューと PDCA 三層）

## 課題
- 週次 PDCA が出した改善案 8件を、AI が全部「人の判断を仰ぐ」に積んだ。中身は減枠・型の見直し・壊れた自動化の修復で、どれも小さく戻せる変更だった
- 「迷ったら提案」は安全に見えて、**改善が1週間止まる＝PDCA が回っていない**

## 何を作るか決めた理由
- 判断の分かれ目を AI の裁量から外し、**種別（kind）から機械的に auto / ask を決める**。直す・減らす・書き換えるは自動。増やす・払う・送る・消すは確認

## 設計
| 自動実行（既定） | 人の判断（例外） |
|---|---|
| fix_broken 壊れた自動化の修復 | increase 件数・頻度の増枠 |
| edit_rule 手順書・ルールの修正 | money 費用が発生する |
| edit_ledger 台帳の追加更新 | external_send 新規の対外送信 |
| schedule_time 時刻・頻度の調整 | public_change 公開ページの料金・名称変更 |
| decrease 削減・一時停止 | irreversible 削除・アカウント作成 |
| content_type 型・構成の変更 | strategy 事業の開始・撤退 |
| experiment 判定ライン付きの小実験 | |
| investigate 調査（読むだけ） | |

- 保護パス（.env・settings・credential・.git）に触る項目は auto でも強制的に ask
- すべての自動変更は**変更前スナップショット**を取り、1コマンドで戻せる
- 判定ライン（--check）と判定日（--due）が無い変更は残さない。判定するのは木曜の週次 PDCA だけ（判定日は自動で木曜に丸める）
- 2回失敗で自動的に人の判断へ格上げ。人にしかできない作業（認証・課金・権限・署名・物理・最終ボタン）だけ「作業待ち」にできる

```
日次（落ちていないか）→ fix_broken だけ修復
週次（効いているか）  → 判定 → 次の改善を起票 → 自動適用
月次（どこに張るか）  → 決議を機械可読の台帳へ → 週次が答え合わせ
```

## 実装
- Python CLI（約950行）：add / list / next / snapshot / done / fail / rollback / approve / reject / verdict / defer …
- 分類の正本と判定日の丸めを抜粋 → [`samples/kaizen_policy.py`](../samples/kaizen_policy.py)
- 経営ダッシュボードの承認ボタン → 即時ヘッドレス実装 → 受け皿は翌朝 4:43 → 最終受け皿は木曜の週次（三段構え）

## 検証
- 週次 PDCA が出した改善の大半が人の手を待たずに適用される状態に。人に上がるのは「増やす・払う・送る・消す」だけ
- **最初に外した仮説**: 「失敗理由の文面から『人がやるべき作業』を自動で拾う」。完了メモに同じ語があるだけで作業待ちカードが出る偽陽性が起きた → 明示フィールドがある時だけ表示に変更

## 守り・責任分界
- 承認＝方針決定であって送信ボタンではない。external_send／public_change／money は承認されても実装は「下書き・変更案まで」
