# 08. 顧客向け Web アプリと経営ダッシュボード

## 課題
- 法人向けサービスの「決済 → 専用環境の発行 → 納品」を人手でやると、1件ごとに手順書を見ながら1時間。ミスも出る
- 施策・KPI・案件・ルーティン稼働が別々の場所にあり、責任者が状況を把握するのに時間がかかる

## 何を作るか決めた理由
- 決済から納品までを無人にし、責任者の仕事を「ダッシュボードで承認・却下する」だけにする

## 設計
```
Stripe Checkout → webhook → 注文を pending で保存
→ 発行バッチ（10分毎・LLM 不使用）が pending を拾う → 1社1環境（Vercel プロジェクト＋PostgreSQL database）を作成
→ 検証4本 → 環境台帳 → 納品メール → 注文を done
```
- 経営ダッシュボード：方針ストリップ（いま → 課題 → 今週 → 今月 → 着地）、施策タブ（改善キュー）、案件タブ（次の一手の承認・「AIに指示」）、SNS／ファネル／ルーティン稼働

## 実装
- Next.js 16／React 19／TypeScript／Tailwind／Vercel。PostgreSQL（Neon）／Stripe。API ルート **42本**（intake・room・dashboard・kaizen・school・checkout・webhook など）
- 認証：ダッシュボードは Google OIDC＋許可リスト。同期 API は共有トークン
- 冪等：done／failed の注文は二度と触らない。再開時は同名の環境があれば作らず使う。発行済み ID は状態ファイルに控える
- 事故ガード：本番プロジェクトを宛先にしたデプロイ・環境変数変更は無条件で中止。秘密値はリポジトリにもログにも書かない
- 無料枠運用：DB に触る頻度を60分に1回へ集約（他バッチも同じ稼働窓に相乗り）

## 検証
- 決済から納品メールまで無人。責任者の操作はダッシュボードの承認ボタンのみ
- 公開デモ：[学習ダッシュボード](https://learning-dashboard-demo-black.vercel.app)（架空データ）／[未来の営業組織](https://mirai-eigyo-soshiki.vercel.app)（全体像の説明サイト）

## 運用改善
- 決裁に添えられたスクリーンショットを AI が必ず読んでから指示を解釈する（文面だけで判断しない）ルールを追加

## 守り・責任分界
- 支払い・返金・アカウント削除は人。webhook の検証と冪等性で二重発行を防ぐ
