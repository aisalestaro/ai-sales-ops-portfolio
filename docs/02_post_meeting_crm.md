# 02. 商談後の自動処理（録画 → 要約 → CRM）

## 課題
- SFA/CRM を売る側（前職）で痛感したこと：**入れても現場は入力しない**。溜まるのは営業が後から書いた二次情報で、経営判断に使えない
- 商談後の入力に20分。入力が遅れると、次のアクションも遅れる

## 何を作るか決めた理由
- 入力をお願いするのをやめ、**録画から自動で CRM を埋める**。現場の行動を変えずにデータが揃う形にする

## 設計
```
商談録画（Meet 文字起こし） → 要約 → CRM へ自動入力（商談メモ・次回日程・温度感）
→ 説明漏れの項目（料金・導入手順・事例）を Slack で担当者に通知 → 類似事例をレコメンド
```

## 実装
- Google Meet の標準文字起こし → Docs を取得（新規 OAuth なし・担当者本人の権限で動く GAS）
- 要約と項目抽出は Claude。抽出項目は**人が書いた定義表**に従う（AI が項目を発明しない）
- CRM API（HubSpot／Zoho／Mazrica）への書き込み。messageId／fileId で冪等

## 検証
| 指標 | 前 | 後 |
|---|---|---|
| CRM 入力 | 20分／商談 | 1分（確認のみ） |
| 入力率 | 担当者依存 | 100%（録画がある商談はすべて） |

- チーム受注率 8%→45% の土台。「説明漏れ通知」で2回目商談の内容が揃うようになった

## 運用改善
- 説明漏れの判定基準（何を話していれば OK か）は営業マネージャーが表を直す。週次で誤判定を見直し

## 守り・責任分界
- 録画データは社内 Workspace 内で完結。LLM に渡すのは文字起こしのみ。受注・失注の確定は人が行う
